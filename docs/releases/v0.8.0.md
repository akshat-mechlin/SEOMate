## 🔑 Real keyword search volumes — Google Keyword Planner

Thanks to [@Galbir](https://github.com/Galbir) ([#51](https://github.com/akshat-mechlin/All-In-One-Free-SEO-Tool/pull/51)).

Until now this tool gave you a *directional* volume estimate from Trends,
autocomplete and SERP signals, and showed you the raw inputs so you could
judge it. That stays. On top of it you can now connect Google's own
Keyword Planner and get the actual numbers: average monthly searches and
competition, straight from the source Google Ads advertisers use.

- **Automatic keyword discovery.** It reads the client's site and market
  and proposes the next best keywords — best demand with least
  competition first, with your already-tracked keywords left out. Tick
  the ones you want, or take the top ten in one click.
- **Feeds the rest of the tool.** Blog and GBP schedules get a "Keyword
  Planner ideas" mode that picks the next keyword automatically, and
  falls back to your tracked keywords when Ads isn't set up. The daily
  agent uses it. There's a `get_keyword_ideas` MCP tool, so you can ask
  Claude for ideas directly.
- **Its own sign-in.** Connecting Ads asks only for the AdWords scope and
  keeps its refresh token separate from the Search Console one.
- Calls go through the open-source
  [google-ads-api](https://github.com/Opteo/google-ads-api) library, so
  the API version isn't ours to maintain.

### Be clear-eyed about the setup before you count on it

This is free of charge and it is **not** a one-click connect, and the
first draft of this release said otherwise. Google
[sunset developer tokens on 9 September 2026](https://developers.google.com/google-ads/api/docs/api-policy/access-levels)
and moved API access to your Google Cloud project. `KeywordPlanIdeaService`
— the service behind these numbers — is a *Planning* service, which the
tier Google approves automatically (**Explorer**) excludes. You need
**Basic** access, and that requires brand verification of the Cloud
project first. A test-level project returns placeholder data, not real
volumes.

So: no money, but a real approval process. Everything else in the tool
works without it, exactly as before.

**Known gap:** the connection currently treats a developer token as
required, and that is the credential Google retired. If you cannot obtain
one, this feature may be unreachable for you. Please
[open an issue](https://github.com/akshat-mechlin/All-In-One-Free-SEO-Tool/issues)
if you hit that — it needs a real Ads account to test properly, and we
don't have one.

## 📅 Content automation got a lot more specific

Thanks to [@Galbir](https://github.com/Galbir) ([#48](https://github.com/akshat-mechlin/All-In-One-Free-SEO-Tool/pull/48)).

- **WooCommerce product posts.** A schedule can draw from the client's
  shop — read through the public Store API, no keys — and post a real
  product with its photo and a button to the product page. Picks rotate
  between top-keyword matches, newest arrivals and a random product, and
  skip anything used in the last 20 items.
- **Google Business Profile buttons and offers.** Choose the call to
  action (Shop, Order, Learn more, Book, Sign up, Call), or post an
  **Offer** that redeems straight on the product page, with a 7-day
  window and an optional coupon.
- **Post length is a setting**, defaulting to 300 characters. Short posts
  get read; the old 1500-character option is gone and the server clamps
  to 150–1000.
- **Keyword choice per schedule** — your top tracked keywords or a typed
  list, used both in the text and to choose which products to feature.
- **Product blog articles.** A draft about one product or a three-product
  roundup, with product cards (image, price, Buy now / See details).
- **Blog drafts export as Markdown.** For Astro, Next.js, Hugo and other
  static sites, download a draft with title/description/slug/date/keywords
  frontmatter. There's also *".md for AI"*, which embeds a brief telling
  an AI how to expand the article.
- **Edit a schedule in place** instead of deleting and recreating it.

### A schedule set for 09:00 could be skipped for a day

Content schedules only ran as a step inside the 24-hour daily agent,
which fires at whatever time the app happened to start. If the sweep ran
before your scheduled hour, that slot was skipped and the next attempt
was a day later. They now run from their own 15-minute runner.

### Romanian keyword ideas came back in Vietnamese

The language id for Romanian was 1040. Romanian is 1032; 1040 is
Vietnamese. The request succeeded, Google answered, and the answer was
for the wrong language — the usual shape of the bugs this project keeps
finding. Also fixed: the language now follows the client's market when
the profile still says `en`, and the keyword research form preselects the
client's own country.

## 🐳 Docker installs could not take screenshots or check ranks

Fixes [#47](https://github.com/akshat-mechlin/All-In-One-Free-SEO-Tool/issues/47), reported by [@Manak-hash](https://github.com/Manak-hash).

The image was built on `playwright:v1.56.0-noble` while `package.json`
had moved to `1.59.1`. That base image carries the browser build for its
own release, and Playwright looks for browsers in a directory named after
the version it was compiled against — so Chromium was present in every
container and invisible to the code. Rank checks, SERP scraping and
screenshots failed on **every** Docker install.

The error said "the headless browser isn't installed", which sounds like
a missing download rather than a version mismatch, and no amount of
running `playwright install` inside the container survived the next
recreate. A test now fails the build if the Dockerfile and `package.json`
ever name different versions again.

**The message also blamed the wrong person.** It told Docker users on
Linux to press a button on a Windows desktop launcher — which was the fix
for [#37](https://github.com/akshat-mechlin/All-In-One-Free-SEO-Tool/issues/37),
where a Windows user had been wrongly told to open a terminal. One
hardcoded answer, wrong for somebody either way. It now answers per
install mode, and says which features actually need a browser, because
most of the tool doesn't.

## 🔒 Carried forward from v0.7.0 (never published until now)

**If you run this with a password or with team accounts, this is the part
that matters.**

- **Data exports skipped the login.** The request gate skipped "any path
  with a dot in it", intended for images and scripts. That also covered
  every export — `/clients/export.csv` (names, emails, phones,
  addresses), keywords, tasks, backlinks, audits, reports, the disavow
  file and the plan PDF. With `APP_PASSWORD` set, all of them downloaded
  with no login.
- **Team roles are now enforced on the server.** "Viewer: read-only" and
  "Member: only assigned clients" were enforced by which pages rendered,
  not by the 424 server actions behind them, which anyone signed in could
  call with any arguments.
- Sign-in attempt limits; portal AI chat and public grader rate limits
  that can't be bypassed with a forged header; Secure cookie behind HTTPS
  proxies; health check no longer leaks the install path.
- **Fixed [#43](https://github.com/akshat-mechlin/All-In-One-Free-SEO-Tool/issues/43):**
  Google Business Profile posting.
- Weekly jobs no longer depend on the app running on a Monday; rank
  checks run daily in rotation and report blocked checks honestly;
  failing jobs back off.
- Backups now download the encryption key alongside `data.db`.
- Updates rebuild the app on next start (they used to keep serving the
  old build).

Full detail: [v0.7.0 notes](v0.7.0.md).

## Upgrading

Nothing to do beyond updating. **No database migrations** in this
release, and the WordPress plugin is unchanged at **0.6.1**.

- **Desktop launcher:** open it and press **Update**.
- **Installer:** re-run the same one-liner from the README.
- **Docker:** `docker compose up -d --build`. The rebuild is what picks
  up the corrected browser image — a plain `docker compose up -d` will
  keep the old one.
- **Git:** `git pull && pnpm install && pnpm build`.

`pnpm install` is required this time: #51 adds the `google-ads-api`
dependency.
