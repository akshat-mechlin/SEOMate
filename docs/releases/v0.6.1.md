# v0.6.1 — All-In-One Free SEO Tool

**Release date:** 2026-10-15
**Diff:** [v0.6.0 → v0.6.1](https://github.com/akshat-mechlin/All-In-One-Free-SEO-Tool/compare/v0.6.0...v0.6.1)
**Commits:** 21 since v0.6.0

Two issues were reported by users. Both are fixed, and looking into them
turned up three more faults nobody had reported — including one that was
quietly corrupting rank history and one that meant rank tracking could
never check a keyword it had not already checked.

Installing is also a different experience: one launcher per computer,
and it fetches Node itself rather than telling you to go and get it.

---

## Reported by users

### "Tracking only supports 8 countries" (#30)

There were three separate hand-written country lists: 48 in the
onboarding picker, 36 in the rank-where tool, 8 in keyword research. The
reporter landed on the one with eight.

They also disagreed about the United Kingdom — two said `GB`, one said
`UK`. That code goes into Google's `gl` parameter *and* onto the keyword
row, so **the same country stored under two codes splits a client's rank
history in half** with nothing on screen to show it happened.

One generated list now: **272 countries**, named from ICU rather than
typed by hand, grouped so the common twenty stay at the top. Existing
`UK` rows map onto `GB` automatically. A test fails the build if a screen
grows its own list again.

### "How do I set which AI model to use?" (#30)

You could not. Every AI feature used the first model in the list for the
active provider, and the only picker in the product lived inside three
chat screens and was forgotten the moment you left them.

There is now a **Model setting in Settings → AI**. If you switch
provider it falls back to that provider's default rather than sending a
model the new provider has never heard of.

### An error report that said nothing (#31)

A user reported a Server Components error. The report contained a
redacted message, no digest, and a "My setup" section where every line
still read *"(run `git rev-parse --short HEAD` in the repo)"*.

That was our fault. The template asked someone whose app had just broken
to go and run git commands.

- **The real error was never stored.** Next hides server error messages
  in production and gives the browser only a digest; the unredacted
  message is available through `onRequestError`, which this app had
  never implemented. The cause went to a terminal nobody was watching.
- **The digest was discarded** — the only thing connecting the notice
  you see to the real error.
- **Version, commit, Node, platform and build mode** are now collected
  rather than requested.

When it happens now, the error screen shows a digest and
**Settings → Errors** holds a row with the same digest and the actual
message.

## Found while fixing those

### Keyword research was asking Google in the wrong language

The country you picked was passed to Google, but the language was
hardcoded to English. A German client got German-*located* suggestions
in English.

Measured on `zahnarzt` with `gl=de`: **two of the top six** came back as
*"zahnarzt near me"* and *"zahnarztpraxis near me"* — phrases no German
searcher types. After the fix the same query returns *"zahnarzt notdienst
heute in der nähe"* and *"zahnarzt für angstpatienten"*; Spanish returns
*"dentista cerca de mi ubicación"*.

Language now follows the country, with a short explicit list of markets
where business search genuinely happens in English (India, Pakistan,
Nigeria, South Africa and similar) — because CLDR answers what people
speak, not what they type into a search box.

### A keyword had to already have a rank before it could get one

The weekly rank sweep asked for keywords whose last check was older than
seven days — over a join that excluded keywords with no check at all. So
**a newly added keyword was never checked, ever**, and the step reported
"no stale keywords" and went green.

Measured on one real install: 25 keywords tracked, 25 never checked,
0 rank readings ever recorded.

Failures are no longer swallowed either. Search engines block addresses
without warning, and the old loop counted only successes — so a rank
tracker that could not read a single page reported "re-checked 0
keywords" and looked idle rather than blocked.

### The repository name was hardcoded in 20 places

Seven of them still said the pre-rename name, including the update
checker and the one-line installer in the README. They worked only
through GitHub's rename redirect, which stops the day anybody registers
the old name — at which point the installer downloads a stranger's zip.

## Installing is different now

The download used to be a folder with `SEO Tool.cmd`, `SEO Tool.command`,
`install.ps1`, `install.sh`, `docker-compose.yml`, `package.json` and
twenty more entries, and nothing to say which to click. And whichever you
clicked, if Node was not installed it told you to go to nodejs.org and
come back.

```
SEO Tool - WINDOWS.hta     <- double-click this
SEO Tool - MAC.command     <- or this
SEO Tool - LINUX.sh        <- or this
READ ME FIRST.txt
_system/                   <- the whole project, out of the way
```

- **Node is fetched for you.** If the machine has none, setup unpacks the
  official portable copy *inside the app folder* — no admin rights,
  nothing added to your system PATH, and a Node you already have is left
  alone.
- **The installer asks whether to start with your computer.** The nightly
  work only runs while the app runs; on one install every scheduled job
  had last run twelve days earlier because the app was simply closed.
- **The download is smaller** — 3.1 MB rather than 4.5, after dropping
  4.2 MB of migration snapshots that are only used to *generate*
  migrations, plus test files and CI config.

## Also in this release

- **Backups from the Desktop launcher are complete.** It preferred the
  `sqlite3` command line and fell back to copying `data.db` — which on
  Windows is the only path, and leaves behind everything still in the
  write-ahead log. Measured: 172 rows live, 171 in the copy, while the
  log said "fine for everyday use". It now uses the same consistent
  snapshot the app itself uses, and **Restore** was added.
- **Nine more checks run unattended**, including a site health check
  daily and render, E-E-A-T and GEO scoring weekly.
- **A skipped task no longer reappears** as a recommendation in the
  client portal or the PDF report.
- **Documentation** lives in the app under Docs, and in this repository.

## ⚠️ Upgrading

- **No migrations in this release.** Nothing to do.
- **The WordPress plugin is unchanged** at 0.6.1.
- Any keyword rows storing `UK` are read as `GB` automatically. Nothing
  is rewritten in your database.
- If you have a model preference, set it once in **Settings → AI** — the
  per-chat pickers were never remembered.
