## New: link intersect

**Sites that link to your competitors and not to you.** Enter your domain
and up to three competitors at **Tools → Link intersect**.

This is the question link building actually starts from, and it is the
one thing in this area that works properly without a paid backlink
index — because it reads pages instead of querying an index of links.

**How it works, and why it matters.** It fetches each candidate page
**once** and asks of that same HTML: does this link to you, and does it
link to each competitor?

The obvious way to build this is to discover your backlinks, discover
theirs, and subtract one list from the other. But both lists are
best-effort, so any link of yours the search happened to miss comes back
as a recommendation to go and ask for a link **you already have**.
Missing links is the normal case without a paid index, so that mistake
would have been common — and invisible. Reading the page removes the
guess.

Sites linking to **two or more** of your competitors rank first. One link
is a decision; three is a pattern, and a page already listing three
companies doing what you do is the one worth writing to. Every row shows
the anchor text and whether the link is dofollow, read from the page's
own `rel` attribute rather than assumed.

It is honest about its own limits: a site can link to you from a page
these searches never surfaced, so "already links to you" means *on a page
we actually read*, and the screen says so.

## Corrections

### Common Crawl was doing nothing in backlink discovery

**Backlink discovery** advertised three sources. One of them had never
returned a single result.

The query was `url=*.<target>&matchType=domain`. Measured against the live
index: that form returns **zero** captures — the `*.` prefix and
`matchType=domain` do not combine, while the bare domain returns rows. So
the step had always been dead, and because an empty result is
indistinguishable from "no backlinks found", nothing ever surfaced it.

**Fixing the query would have made results worse.** `matchType=domain`
returns pages **on** the target and its subdomains, not pages linking to
it, and those were only excluded on an exact hostname match. So
`blog.yoursite.com` would have passed as a backlink candidate, the
confirm step would have found the ordinary nav link back to the homepage,
and reported a site's **own subdomain as its backlink**, with anchor text.

There is no cheap correct version — that data lives in Common Crawl's
bulk web-graph files, which are gigabytes per crawl and not an API. So it
is gone, and the tool now describes two sources it genuinely uses.

### The competitor playbook used a worse copy of code it already had

The playbook's backlink list came from its own private implementation:
two searches, no page fetching, and a comment stating that *"there's no
free way to know for sure"* whether a link was dofollow without fetching
each page.

The module next to it had been fetching each page and reading the `rel`
the whole time.

So the playbook showed unverified mentions described as probable dofollow
links — **and passed those unverified domains to the AI summary under the
heading "Linked from external sites"**, so recommendations were written
from links that had never been shown to exist. There is one
implementation now, the follow status shown is real, and the summary
receives confirmed links only.

### Five broken links, two of them on the repository front page

The README's top navigation linked `TROUBLESHOOTING.md` and `ROADMAP.md`
at the repository root. Both files live in `docs/`, so GitHub returned
**404** — the single link a stuck user clicks went nowhere, and had done
for as long as the files had been in `docs/`.

Three more were pointing one directory too high. Those were found by the
new test on its first run, not by anybody reading.

The build now fails when a relative link in any published markdown file
does not resolve, and separately when it resolves on the maintainer's
disk but points at a file that is not published — which is how a link can
work for us and 404 for you.

### "99 dedicated tools" was never 99

Counted rather than remembered: **92**. The README said 99 in five
places, while the tools page in the app listed 91 (before this release's
new tool) and the documentation site generated 91 from the source.

The count now comes from the generated capability table, which is derived
from the app's own code.

### The release zip promised a checksum file it did not ship

The README said *"every release ships a `.sha256` next to the zip."* Only
v0.6.0 ever did. The checksum is published in the release notes, which is
what the README now says.

## Documentation and repository

- **Documentation is linked from the front page** — in the top navigation
  and in a section of its own, with a row per module.
- **The four Claude Code skills are documented.** `plugins/seo-tool`
  ships them — audit report, client setup, fix pass, keyword plan, each a
  multi-step workflow over the MCP tools — and nothing outside that
  folder had ever mentioned them. One honest note added with them: the
  plugin has a valid manifest but the repository has no marketplace
  manifest, so there is no one-command install for it yet.
- **A question the FAQ never answered:** can a ChatGPT Plus or Claude Pro
  subscription be used instead of an API key? No — they are separate
  products on separate billing, and no amount of work here changes that.
  But the thing people want works pointed the other way round: connect
  your chat app **to** this tool over MCP and your subscription does the
  thinking, with no API key at all.
- **Internal planning notes are no longer published.** The competitive
  review, the MCP plan, the audit prompts and a generated agent stub were
  on the public repository; the release script had already been excluding
  them from your download as "notes to ourselves". They are local-only
  now. Nothing user-facing was removed.

## ⚠️ Upgrading

- **No migrations.** Nothing to do.
- The WordPress plugin is unchanged at 0.6.1.
- Link intersect needs **no API key and no AI provider**. It does use the
  headless browser's network path, so if rank checks work for you, this
  will too.
